# Studio Claw

A fully local, multi-agent **image desk**. People chat on Discord or WhatsApp — text, or text plus a reference image — and get images back that they can keep refining in conversation. Every image passes an independent reviewer before anyone sees it.

Nothing leaves the box. Reasoning and vision run on a local [vLLM](https://github.com/vllm-project/vllm) server (Qwen3.6-35B NVFP4 on a Dell GB10); images are generated by a local [ComfyUI](https://github.com/comfyanonymous/ComfyUI). Discord and WhatsApp are only the transport. Orchestration is [OpenClaw](https://openclaw.ai) 2026.7.1.

Built for the Dell Boston hackathon.

---

## How it works

```
Discord / WhatsApp ─► DESK  new request? → ticket.py create (v1) → "Filed T-… → artist"
                        │  iteration?    → ticket.py revise --change "…"  (v2, v3, …; "back to v2" works)
                        │  writes a spec: must-haves + avoid list (+ reference, or base image + change)
                        │
                        ├─► ARTIST   comfy_gen.py → ComfyUI → ticket.py submit
                        │
                        ├─► REVIEWER checks the image against the spec (and against the base, on an iteration)
                        │      ACCEPT → ticket.py accept
                        │      REJECT → ticket.py reject --reason "fix 1; fix 2"   (attempt +1)
                        │                 └─► desk re-spawns the artist with the feedback
                        │                      (3 rejects on one version → post best attempt, person keeps iterating)
                        │
                        └─► posts "T-… v2" + image → ticket.py close → "Reply with changes to iterate"

"history" → every version with its verdict   ·   "status" → the board   ·   "stats" → first-try acceptance, attempts, versions
```

Two nested loops keep quality and iteration separate:

- **Versions** — the requester's loop. "make it bluer", "go back to v2 but bigger". Each round is a new version on the *same* ticket, built from the previous version's prompt and image so the subject stays recognisable. Unlimited by default; cap with `TICKET_MAX_VERSIONS`.
- **Attempts** — the reviewer's loop. Within one version the reviewer can send work back up to `TICKET_MAX_ATTEMPTS` times (default 3). Exhausting it marks the version `failed` and the desk posts the best attempt anyway. The cap resets on every new version.

## The three agents

Each runs in its own OpenClaw workspace with only the tools it needs, so roles can't blur.

| Agent | Job | Tools |
|---|---|---|
| `desk` (default) | Talks to people, owns tickets, orchestrates artist → reviewer → retry. Never draws, never judges. | `read`, `exec`, `view_image`, `message`, `agents_list`, `sessions_spawn`, `sessions_yield`, `subagents` |
| `artist` | Turns one spec into one image through ComfyUI, then submits. No self-review. | `read`, `exec`, `view_image`, `image_generate` |
| `reviewer` | Independent ACCEPT/REJECT against the spec. Cannot generate images. | `read`, `exec`, `view_image` |

The minimum viable version is desk + artist; the reviewer is the quality gate and the demo story.

Which OpenClaw features that exercises:

| OpenClaw feature | Used for |
|---|---|
| **Channels** (`channels.discord`, WhatsApp plugin) | Receiving messages and attachments, posting images back |
| **Multi-agent** (`agents.list`, per-agent workspace `AGENTS.md`, tool allow/deny) | The three roles, each sandboxed to its own tools |
| **Sub-agents** (`sessions_spawn` / `sessions_yield`) | The desk orchestrating artist → reviewer → retry |
| **Sessions** (one per channel) | Conversation memory, so "make it bluer" knows what "it" is |
| **Skills** (`~/.openclaw/skills/tickets`) + `exec` | The ticket store the agents operate |
| **Image provider** (`plugins.entries.comfy`) | Local ComfyUI on `127.0.0.1:8188` |
| **Model provider** (`models.providers.vllm`) | Local Qwen3.6 on `127.0.0.1:8000` for reasoning *and* vision |

## The ticket store

`skills/tickets/ticket.py` is a single-file SQLite store (stdlib only, no dependencies). Every command prints JSON with an `ok` field, except `history` and `list --md`, which print markdown for posting straight into a channel.

```
new ──start──► in_progress ──submit──► review ──accept──► resolved ──close──► closed
                    ▲                     │                                     │
                    └──────reject─────────┘  (attempt + 1, failed past the cap)  │
                    ▲                                                            │
                    └──────revise (version + 1, attempt reset) ◄──────────────────┘   (also from failed)
```

| Command | Who | What |
|---|---|---|
| `create --summary … --request … --assignee … [--category --priority --source --channel --requester]` | desk | File a ticket (`T-YYYYMMDD-NNN`) |
| `start <ID> --agent <id>` | worker | Pick it up |
| `note <ID> --agent <id> --text …` | anyone | Progress note |
| `submit <ID> --agent artist --result "<prompt>" --artifact /abs/path.png` | artist | Hand in for review; records version + attempt |
| `accept <ID> --agent reviewer --notes …` | reviewer | Approve → `resolved` |
| `reject <ID> --agent reviewer --reason "<fixes>"` | reviewer | Send back, attempt + 1 |
| `resolve <ID> --agent <id> --result …` | worker | Finish without review |
| `close <ID>` | desk | Delivered to the requester |
| `revise <ID> --change "<their words>" [--from-version N]` | desk | New version; returns `base` = prompt + image to build from (`reopen` is an alias) |
| `fail <ID> --agent <id> --reason …` | anyone | Could not be done |
| `show <ID>` · `history <ID>` | anyone | Full JSON · markdown table of every version |
| `list [--status S] [--channel C] [--requester R] [--md]` · `stats` | desk | Board · metrics |

`stats` reports first-try acceptance rate, average attempts per accepted version, average versions per ticket, and average minutes to resolve — the numbers the reviewer loop exists to move.

The script enforces the transitions above and refuses anything else, so a confused agent can't corrupt the board.

## Image generation

`skills/tickets/comfy_gen.py` queues one prompt on the local ComfyUI, polls `/history`, downloads the result into `$DESK_OUT`, and prints `{"ok": true, "file": …, "seed": …, "seconds": …}`. It also:

- injects a shared negative prompt that blocks text, watermarks and logos — so prompts never have to say "no text" (naming it makes SDXL draw it);
- stamps a random (or `--seed`-pinned) seed into every KSampler, so iterations can be made reproducible;
- prefixes saved files with the ticket id.

Two workflows are wired up: `sdxl` (prompt node `6`) and `zit` (Z-Image, prompt node `27`), selected with `--model` or `$DESK_MODEL`, loaded from `$KIT/workflows/`.

## Quick start

On the GB10, roughly five minutes. See [`ticket-desk/README.md`](ticket-desk/README.md) for the detailed version.

```bash
# 1. Local model + ComfyUI
bash ~/kit/restore.sh vllm
curl localhost:8000/v1/models      # reasoning + vision
curl localhost:8188/system_stats   # image generation

# 2. OpenClaw
npm i -g openclaw@2026.7.1
echo 'DISCORD_BOT_TOKEN=...' >> ~/.openclaw/.env   # Message Content Intent must be ON

# 3. Install the desk
GUILD_ID=<your discord server id> bash ticket-desk/setup.sh

# 4. Run
set -a; . ~/.openclaw/.env; set +a; openclaw gateway
```

Then, in the Discord server:

```
make a cozy mushroom lantern, pink cap, warm glow
make the cap blue
bigger glow
go back to v1 but make it blue
history        status        stats
```

Attaching a reference image and asking for something in that style files a new ticket.

## Configuration

| Variable | Default | Used by |
|---|---|---|
| `DISCORD_BOT_TOKEN` | — (you add it to `~/.openclaw/.env`) | OpenClaw Discord channel |
| `GUILD_ID` | — (required by `setup.sh`) | Substituted into the config patch |
| `VLLM_API_KEY` | `vllm-local` (written by `setup.sh`) | vLLM provider |
| `TICKET_DB` | `~/.openclaw/tickets.db` | `ticket.py` |
| `TICKET_MAX_ATTEMPTS` | `3` | Reviewer retries per version |
| `TICKET_MAX_VERSIONS` | `0` (unlimited) | Requester iterations per ticket |
| `KIT` | `~/kit` | Where `workflows/*.json` live |
| `COMFY_URL` | `http://127.0.0.1:8188` | `comfy_gen.py` |
| `DESK_OUT` | `~/desk-out` | Where generated images are saved |
| `DESK_MODEL` | `sdxl` (`sdxl` \| `zit`) | Which ComfyUI workflow to use |
| `DESK_NEGATIVE` | text/watermark/crop blocklist | Shared negative prompt |

Tuning the behaviour itself is mostly editing prose: the spec format lives in `workspaces/desk/AGENTS.md`, the prompt recipe in `workspaces/artist/AGENTS.md`, and the quality bar in `workspaces/reviewer/AGENTS.md`.

## Requirements

- A Dell GB10 (or any box that can hold the model and ComfyUI), Linux
- vLLM serving `nvidia/Qwen3.6-35B-A3B-NVFP4` on `:8000` — text **and** vision
- ComfyUI on `:8188` with an SDXL (and optionally Z-Image) API workflow in `$KIT/workflows/`
- Node.js for `openclaw@2026.7.1`; Python 3 (stdlib only) for the skill
- A Discord bot with Message Content Intent, and/or the OpenClaw WhatsApp plugin

## Status

The config keys come from the OpenClaw 2026.7.1 docs shipped on the kit and haven't been run against a live gateway yet; if one is rejected, `openclaw config patch --dry-run` names it. Reference images are currently *described* and their traits carried into the prompt — true img2img (LoadImage → VAEEncode → KSampler at denoise ≈ 0.6) is the stretch goal. Troubleshooting table: [`ticket-desk/README.md`](ticket-desk/README.md#debugging).
